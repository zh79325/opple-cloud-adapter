## 1. 使用的系统与方式

本项目没有引入第三方配置库，采用**手写 JSON 文件 + 环境变量 + Node.js `process.env`** 的轻量组合：
- CLI 凭据持久化到用户主目录下的 `~/.opple-cli.json`。
- Web 服务将家庭/房间/设备树快照与设备位置布局分别持久化到 `data/local-tree.json` 与 `data/device-positions.json`。
- 运行时通过 `process.env.OPPLE_TOKEN`、`process.env.OPPLE_PROJECTCODE`（CLI）和 `process.env.PORT`（Web）覆盖默认值。
- 硬编码常量（API base URL、clientid、app-version、默认端口等）直接写在源码中，无外部配置文件。

## 2. 关键文件

- `src/opple/client.js` — `OppleClient` 类，定义 `CONFIG_PATH = join(homedir(), '.opple-cli.json')`，实现 `loadConfig()` / `saveConfig()`。
- `src/cli.js` — CLI 入口，`getClient()` 优先读取 `OPPLE_TOKEN` / `OPPLE_PROJECTCODE` 环境变量，否则调用 `OppleClient.loadConfig()`。
- `src/opple/server.js` — Web 后端，定义 `PORT`、`WEB_DIST`、`POS_FILE`、`TREE_FILE` 等路径常量，并提供 `loadTreeCache()` / `saveTreeCache()` / `loadPositions()` / `savePositions()` 读写 data 目录。
- `package.json` — 声明 `bin.opple` 指向 `bin/opple.js`，并定义 `scripts.web` 启动 `src/opple/server.js`。

## 3. 架构与约定

### 3.1 配置来源优先级（CLI）
`src/cli.js:37-42` 明确实现两级加载：
1. 若 `process.env.OPPLE_TOKEN` 且 `process.env.OPPLE_PROJECTCODE` 同时存在 → 用环境变量构造 `OppleClient`。
2. 否则 → 调用 `OppleClient.loadConfig()` 从 `~/.opple-cli.json` 读取。
这意味着环境变量是**临时覆盖**，磁盘文件是**持久化凭据**。

### 3.2 凭据文件格式
`~/.opple-cli.json` 由 `OppleClient.saveConfig()` 写入，结构为：
```json
{
  "token": "...",
  "projectCode": "...",
  "base": "https://iot2.opple.com"
}
```
字段名与 `constructor(opts)` 解构一一对应；`base` 可选，缺省走 `DEFAULT_BASE`。

### 3.3 Web 服务配置
- `PORT`：`Number(process.env.PORT ?? 5170)`，默认 5170。
- `WEB_DIST`：固定为 `../../web/build`，即前端构建产物目录。
- `POS_FILE`：`../../data/device-positions.json`，存储每个家庭/房间的灯位坐标与尺寸。
- `TREE_FILE`：`../../data/local-tree.json`，存储 `{ syncedAt, tree }` 形式的云端树快照，用于避免每次请求都拉取云端。

### 3.4 数据分层策略
`server.js` 对 `/api/tree` 接口实现“本地缓存优先”：
- 若 `local-tree.json` 存在 → 直接返回，source=`local`。
- 否则调用 `client.tree()` 拉取云端，落盘后返回，source=`remote`。
- 无论 source 为何，设备位置数据始终实时合并（`treeWithPositions`），不受快照影响。

### 3.5 硬编码常量
以下值以常量形式内嵌在 `client.js` 中，未暴露为可配置项：
- `DEFAULT_BASE = 'https://iot2.opple.com'`
- `CLIENT_ID = 'opple_smarthome'`
- `APP_VERSION = '5.8.0'`
- 所有 API 路径（如 `/api/Device/FindDeviceListByPage`、`/businessapi/Room/FindUserRoomList` 等）均硬编码在方法体内。

## 4. 约定与约束

- **CLI 凭据必须通过命令保存**：`OppleClient.loadConfig()` 在 `~/.opple-cli.json` 不存在时抛出错误 `"未找到配置文件 ~/.opple-cli.json，先用 "opple token save <token> <projectCode>" 保存"`，这是唯一被代码强制校验的规则。
- **环境变量覆盖范围限定**：仅 `OPPLE_TOKEN` 与 `OPPLE_PROJECTCODE` 两个变量生效，其他环境变量（如 `OPPLE_BASE`）不被读取。
- **Web 端口默认 5170**：由 `server.js` 中的 `process.env.PORT ?? 5170` 决定，可通过环境变量覆盖。
- **data 目录结构约定**：`device-positions.json` 按 `projectCode -> gpno -> { shape, devices, excluded }` 组织，`local-tree.json` 按 `{ syncedAt, tree }` 组织，读写函数对这些结构做了最小校验（如 `Array.isArray(raw?.tree)`、`Array.isArray(room?.excluded)`）。
- **Node 版本约束**：`package.json` 的 `engines.node >= 22`，配合 `import` ESM 语法与 `fetch` 全局 API，意味着运行环境必须是较新的 Node。
- **无 feature flag / 多环境切换机制**：项目没有 `.env` 文件、没有 `config/` 目录、没有 YAML/TOML 配置，也没有区分 dev/prod 的配置分支——所有差异通过环境变量或硬编码常量处理。
